The problem

Urban congestion imposes delay, fuel cost and emissions, yet it is often measured only after it occurs. A system that both detects where congestion is forming and forecasts where it is heading gives planners and drivers time to act.

The solution

FlowCast combines a traffic dashboard, a prediction module, hotspot analytics, an alert centre and a data-management pipeline. It ships with a seeded synthetic dataset so every screen is functional without a paid traffic API, and isolates any real provider behind an adapter so the core system is never locked to one vendor.

Workflow

1

Ingest

Load historical traffic records — timestamp, road, speed, volume, occupancy, weather, incidents, events.

2

Engineer

Derive lag features, rolling statistics, peak-hour flags and congestion labels from defensible thresholds.

3

Model

Compare a baseline against a tree-based model using a chronological split to avoid leakage.

4

Act

Surface hotspots, forecasts and alerts on the dashboard, then export results for reporting.

Metrics & honesty

Evaluation metrics are reported for the model actually used on each forecast, and regression and classification metrics are kept separate. In Demo Mode the numbers are computed on synthetic data — they illustrate the workflow and are not claims about real-world accuracy.

Real-world forecasting quality depends entirely on the quality, coverage, timeliness and representativeness of the actual traffic data connected.

FAQ

Is this connected to live traffic data?

No. The default experience runs in Demo Mode on seeded synthetic data. A real traffic provider can be connected later through the adapter layer, keeping API keys server-side.

Does the demo need a paid API?

No. Every module works with the built-in generator, and the chart and map libraries degrade gracefully to local fallbacks if the CDN is unavailable.

How is the congestion label decided?

Labels are derived from the ratio of observed speed to the road's free-flow speed, using fixed thresholds — not arbitrary random assignment.

Can I export my results?

Yes. The Data view exports the processed dataset and analytics results to CSV.

Overview

FlowCast is a full-stack SaaS prototype for traffic congestion detection, hotspot analytics and short-term forecasting. The standalone frontend is provided by index.html and script.js; the optional backend exposes FastAPI JSON endpoints and runs the ML pipeline.

Demo Mode is the default: seeded synthetic data powers every screen, and no paid API is required. Real traffic feeds are connected through an adapter so the core system stays vendor-neutral.

Running Demo Mode

No build step or backend is required for the frontend. Serve the project folder with VS Code Live Server, create an account, and sign in to use every module against the built-in generator.

# Backend (optional, for real predictions)

pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# Point the frontend at the backend
localStorage.setItem('flowcast.apiBase','http://localhost:8000')

Administration & account roles

This prototype does not include an admin dashboard or administrator permissions. New accounts are local analyst accounts; the role label is not enforced by a server. Do not use browser-side roles to protect real user or operational data.

A production admin area requires backend authentication, server-enforced role checks, a controlled way to grant/revoke admin access, and audit logging.

Security notes

  • Authentication in this file is a client-side demo so the prototype runs with no backend. It is not production-grade.
  • In production, move auth to the backend: hash passwords with a salted algorithm such as bcrypt or Argon2, issue short-lived tokens, and validate every request server-side.
  • Never place API keys or secrets in frontend code — load them from environment variables on the server.
  • Validate and sanitise all uploaded filenames and data, enable CORS only for known origins, and add rate-limiting middleware.
